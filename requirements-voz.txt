# Pacotes da voz que TÊM de ser instalados com `--no-deps`.
#
#   pip install --no-deps -r requirements-voz.txt
#
# ── Porque existe este ficheiro ─────────────────────────────────────
#
# Os dois motores de voz discordam sobre a versão do `awscrt`:
#
#     amazon-transcribe 0.6.3/0.6.4  ->  awscrt~=0.26.1
#     smithy-http[awscrt]            ->  awscrt~=0.32.0
#
# E não é cosmético de um lado: o `smithy_http.aio.crt` importa
# `awscrt.aio.http`, um módulo que **não existe** no 0.26.1. Com o CRT
# antigo o Nova Sonic morre na construção do cliente, com a mensagem
# enganadora «awscrt is not installed».
#
# O pino do `amazon-transcribe`, esse, é conservadorismo do
# empacotador. **Medido:** com `awscrt==0.37.0` ele faz uma transcrição
# em streaming de verdade contra eu-west-1, em espanhol, e devolve o
# texto certo. Os dois convivem — só o resolvedor do pip é que não
# deixa, porque lê o que está declarado e não o que funciona.
#
# ── Porque num ficheiro à parte, e não num `pip install` à mão ──────
#
# Já nos aconteceu: um `pip install` sem versão a correr DEPOIS do
# `requirements.txt` actualizou o pytest e rebentou a recolha dos
# testes. A lição foi "com versão, sempre".
#
# Aqui o `--no-deps` torna esse acidente impossível por construção —
# nada mais no ambiente pode ser tocado — e o pino continua exacto. É
# mais seguro do que uma linha solta num workflow, e diz porquê a quem
# o encontrar.
#
# ── Quando apagar isto ──────────────────────────────────────────────
#
# Quando o Sonic substituir a cascata e o `amazon-transcribe` sair de
# vez. Até lá os dois têm de caber no mesmo processo, senão a bandeira
# de funcionalidade não existe — e sem bandeira a passagem é uma porta
# de sentido único, num produto que é demonstrado a clientes.
amazon-transcribe==0.6.4
