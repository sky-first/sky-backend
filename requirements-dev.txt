# **Porque isto é uma linha e não uma lista.** Até 26/08/2026 este ficheiro era
# uma segunda cópia completa da lista de produção, com pinos mais velhos. Seis
# pacotes divergiam, e um deles partia o ambiente de quem instalasse os dois:
#
#     requirements.txt      cryptography==48.0.1
#     requirements-dev.txt  cryptography==42.0.2
#
# Ficava-se com os metadados de uma versão e o binário nativo da outra, e doze
# testes de MFA falhavam com *"The version of cryptography does not match the
# loaded shared object"* — uma mensagem que manda criar um ambiente novo e não
# diz que a causa está aqui.
#
# Os outros cinco divergiam em silêncio: `sqlalchemy` 2.0.25 contra 2.0.36,
# `python-jose` 3.3.0 contra 3.4.0. Quem desenvolvia testava contra bibliotecas
# que não eram as que corriam em produção.
#
# E a lista já nem servia o seu propósito: acrescentava **um** pacote
# (`pytest-timeout`) e deixava de fora **trinta e um** que a aplicação usa —
# celery, boto3, os conectores todos. Quem instalasse só este ficheiro não
# conseguia sequer arrancar o servidor.
#
# Herdar resolve a classe inteira do problema: há um sítio só onde se fixa uma
# versão, e as duas listas não podem voltar a divergir.
-r requirements.txt
